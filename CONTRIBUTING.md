# Contributing to Una Labs repositories

Una Labs currently accepts contributions only where a repository explicitly enables them.

Before opening a pull request:

1. Open or reference an approved issue.
2. Keep the change bounded to the stated product and acceptance criteria.
3. Add or update proportional automated tests.
4. Run the repository's documented checks.
5. Remove secrets, personal data, generated credentials, and unrelated files.
6. Describe user impact, security impact, validation, and rollback considerations.

Passing builds are implementation evidence, not proof that a change is deployed or production-ready. Maintainers may require additional privacy, security, accessibility, or release evidence before merge.
